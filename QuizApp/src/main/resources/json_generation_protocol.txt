1. Golden Rules

    No Hallucination: Only generate questions for content explicitly present in the provided source material (images/text). If the section isn't in the source, the JSON is empty for that section.

    Strict Numbering: Use the exact chapter and subchapter numbers printed on the source material. Do not assume or guess the textbook's table of contents.

    Atomic Grading: Every question must be based on a specific, identifiable paragraph or code block in the source.

    One Subchapter at a Time: Process only the material provided in the current prompt/scan. Do not jump ahead.

2. JSON Structure Template

Every question object must strictly follow this structure:
JSON

{
  "id": "module_subchapter_qNumber",
  "metadata": { 
    "module": "Java", 
    "chapter": "X.X.X" 
  },
  "content": { 
    "question_text": "...", 
    "question_type": "concept/code/boolean/list" 
  },
  "grading_instructions": {
    "core_requirements": ["Requirement 1", "Requirement 2"],
    "acceptable_variations": ["Variation 1"],
    "strictness_level": "strict/moderate/lenient"
  }
}

3. Field Constraints

    id: Must be globally unique (e.g., java_4_3_1_q1).

    chapter: Must match the source text's header exactly (e.g., "4.3.1").

    question_type: Must be one of concept, code, boolean, or list. If list, include "expected_count": N.

    strictness_level: * strict: High accuracy required (exact definitions/syntax).

        moderate: Concepts explained in user's own words are acceptable.

        lenient: Focus on understanding the core mechanism.

4. Junior Role Filter

    Context: The user is preparing for internship and junior Java developer applications (target: October). Generate questions only for content that a junior developer would realistically need to know.

    Skip entirely (produce no questions) for:
        Historical trivia (e.g. why a keyword got its name, evolution of Java versions)
        Highly advanced or niche features unlikely to appear in junior interviews (e.g. record patterns, compact compilation units, native methods)
        C++/Python/C# comparisons and footnotes
        Content from Note/Tip/Caution boxes unless the note contains a critical junior-level rule (e.g. "never do X")
        Deprecated APIs and legacy classes (e.g. GregorianCalendar, Date) — mention LocalDate alternatives only

    Always include questions for:
        Core OOP concepts (encapsulation, inheritance, polymorphism, abstraction)
        Access modifiers (private, public, protected, default)
        Constructors, methods, fields, static vs instance
        Null handling and NullPointerException
        Common design rules (e.g. make fields private, use accessors)
        Call by value behavior
        Any concept that commonly appears in junior Java interviews

5. Operational Procedure

    Receive Scan: User uploads file.

    Verify Section: Model confirms the section number explicitly stated on the page.

    Generate: Model produces JSON only for that section.

    Confirm: Model waits for user to check the output before proceeding to the next section.
